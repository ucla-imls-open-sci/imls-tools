# Standards audit: wbcheck and Carpentries guidance

Date checked: 2026-09-30. Review ID prefix: **STD**. Evaluation and design only.

## Verdict and scope

wbcheck is a useful local authoring aid, with a small registry, offline rubric snapshots, structured findings, and substantial regression coverage. Several messages nevertheless promote a limited observation into a stronger accessibility or pedagogical conclusion. Correct those claims before adding more rules. Passing this tool does **not** establish Carpentries approval, accessibility compliance, teaching readiness, or pedagogical quality.

Reviewed `main` at **9032b056c2a3a18a12068f9db1e6c7a7c7e5136e**, package 0.2.1. The working tree was clean at the start. This review adds only three dated design documents. No implementation, commits, external writes, paid review calls, or model downloads. Applicable ancestor AGENTS instructions, project registry, README, CONTRIBUTING, CHANGELOG, pyproject.toml, pixi.toml, CI, registry, detectors, output consumers, tests, and relevant design notes were read. Historical assessments were treated as intent, not descriptions of current code.

The current release already distinguishes WB401/WB009 editorial suggestions from automatic fixes; the AI issue body already warns that a matched quotation does not validate the judgment. Recent persistence, partial-scope, stale-AI, and atomic-results fixes are present. These are improvements, not outstanding findings from earlier reviews.

## How the implementation works

`app.check` calls the shared `refresh.refresh`, which resolves a local path or temporary clone, reads config/support files, and invokes `lesson_check.run_checks`. Discovery scans top-level `.md` and `.Rmd` files in `episodes/`, including intentionally unlisted drafts, in filename order. Config ordering is checked separately; it does not set the checker traversal order. Source parsing uses regexes plus a fence mask, not the rendered Workbench document. Front matter, divs, headings, inline links, placeholder text, objectives, and contractions emit mechanical `Finding` objects.

`app.review` uses the direct Claude or Ollama backend through `ai_review.review_episode`. Pinned rubric files enter the system prompt; episode/glossary content enters the user prompt as untrusted data. `EpisodeReview` validates response shape; `locate_quote` checks normalized, ordered quote fragments and derives the first matching source line. `to_findings` caps output at 12 and maps eight areas to AI codes. This validates an anchor, not the criticism. Ollama retries malformed JSON once and uses a 900-second timeout. Claude checks refusal, truncation, and missing parsed output. SDK behavior and live model quality were not exercised.

`refresh` preserves other reviewed episodes, marks AI findings stale after source changes, keeps occurrence numbering, applies ignores, and writes results atomically. `Results` version 2 reads versions 1 and 2. Findings contain severity, category, message, location, hint, line, code, quote, source, scope, stale, and occurrence. `Rule` contains only code, name, title, why, and guide tuples: actual severity lives at each detector. The rule code identifies a check; it is **not** the ID of an individual finding, despite the registry module's opening description.

Mechanical identity is code/category + relative location + normalized message, with an occurrence suffix before a truncated SHA-1 hash. AI identity uses normalized quote instead of message. Suppression compares codes, path globs, or finding IDs. Issue deduplication compares hidden 12-hex finding markers in existing issues, including closed issues. Serialized `id` and `guides` are currently derived values and discarded by the loader. This makes migration a behavioral change, not merely a dataclass edit.

Current consumers are `console.render_findings` for the Typer CLI; `report` for legacy terminal/Markdown/JSON and Quarto HTML/PDF; `FindingsApp._update_detail` for the TUI; and `issues._body` for issue drafts. They repeat presentation decisions, especially “Fix” and source links. Issue bodies already deduplicate static explanations by rule. TUI guide labels are terminal hyperlinks without a visible URL. There is no `explain` or `rules` command. WB103 and WB213 are automatic-fix candidates; WB401 and WB009 require individual editorial confirmation. Fix code still extracts some values from message text, so new diagnostic templates must be tested against fix planning.

### Scope differences and genuine tensions

- Lab review concerns the rendered website; wbcheck scans unpublished episode drafts too. Keep authoring assistance, but label draft context and do not imply all findings obstruct submission.
- CT-A suggests an illustrative 15–20-minute assessment interval, while LE Content aims at 10–15 minutes. Do not merge these into a universal numerical requirement. Neither interval can be proved from a single episode duration.
- CLDT advises avoiding contractions; LR asks reviewers to consider extensive use. WB404's numerical threshold belongs to wbcheck, not either source.
- General image-description wording in communications guidance is qualified by the technical Workbench decorative-image convention and by Lab guidance permitting detailed descriptions in nearby text. Do not flag intentional `alt=""` as inherently inaccessible.
- Pandoc 3.11 accepts an implicitly closed final div. pegboard 0.7.9 rejects the same source before validation. WB203 is defensible as Workbench compatibility; this is **not** evidence for retiring it as a Pandoc false positive.
- Automatic anchor suffixes prevent the duplicate-text collision alleged by WB212's rationale. pegboard still has a narrower within-hierarchy uniqueness rule. Both facts can hold.
- The older lifecycle design note's “clear these to reach alpha” and error-count proxy for beta are too strong. Missing a known scaffold fingerprint does not establish completion or readiness. Display a human checklist, never infer promotion.

## Coverage worth adding, and what to leave to people

| Gap | Feasible method | Useful boundary |
|---|---|---|
| Explicit/multiline alt attributes, decorative markers, reference images | Deterministic supported-syntax parser | Separate attribute presence from adequacy; R-generated figures need rendered output or an explicit unverified status. |
| Nonboolean, finite nonnegative timing values; invalid config episode-list types | Deterministic | Inputs/metadata validation, not duration recommendations. |
| Objective list items independent of marker, nesting depth, wrapping | Deterministic syntax extraction | Count top-level objectives consistently, then apply a recommendation. |
| Challenge/solution ancestry; sibling heading uniqueness | Deterministic structure plus heuristic interpretation | Use a small shared structural representation only for demonstrated needs; do not replace the whole parser on preference alone. |
| External glossary links and alternate local paths | Deterministic discovery, heuristic coverage | Recognize accepted alternatives without fetching them in ordinary checks or declaring coverage complete. |
| Assessment-to-objective alignment, jargon definition, exercise feedback | AI assistance plus author review | Need learner/lesson context and explicit uncertainty; no quote-only proof. |
| Contrast, useful figure description, assistive-technology experience | Human/rendered accessibility review | A source text-only AI cannot measure contrast or see the figure. |
| Setup works on supported systems, correct results, data licensing suitability | Execution/manual review, optionally deterministic file-presence assistance | Never confuse a present file/license string with successful setup/legal suitability. |
